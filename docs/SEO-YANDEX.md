# SEO и подготовка продвижения PHOTO ID

Проверено 8 октября 2026 года. Рабочий сайт: `https://evgenii-nikonov.github.io/photoid/`.
Планируемый домен владельца: **фотоайди.рф**, технический адрес: `xn--80aimcxa1ao.xn--p1ai`.

## Решение и выполненные изменения

Сайт остаётся статическим. Для двух страниц достаточно метаданных в исходном HTML, sitemap и микроразметки; SEO-плагин, серверный рендеринг и новый фреймворк не нужны. Генератор `scripts/update_seo.py` обновляет обе страницы и sitemap из одного адреса в `config/site.json`, чтобы при переезде не осталось разных доменов.

- Уникальные title и description с назначением услуги и Новосибирском. Исправлены несовпадающие 15 и 15–20 минут и обещание «без очередей» в старом description, не подтверждённое содержимым страницы.
- Абсолютный canonical: главная `/photoid/`, прайс `/photoid/price.html`. `/index.html` и версии с рекламными параметрами рекомендуются к объединению с главной; сам URL и рекламные метки JavaScript не переписывает.
- `sitemap.xml`: только две канонические страницы, без выдуманных lastmod, query и якорей.
- JSON-LD LocalBusiness, WebSite, WebPage, два видимых предложения 450/850 ₽, BreadcrumbList для прайса. Адрес, телефон и часы взяты из существующей страницы. Рейтинги, отзывы, координаты и реквизиты не выдумывались. Разметка не гарантирует расширенный сниппет.
- Open Graph и обложка 1200×630 из настоящего логотипа и портрета. Заголовки, прайс, контакты и FAQ доступны в HTML без JavaScript.
- Существующие категории прайса пригодны для быстрых ссылок рекламы; звонки и мессенджеры работают без формы и без аналитики.

Основание: [canonical в Яндексе](https://yandex.ru/support/webmaster/ru/robot-workings/canonical), [Sitemap](https://yandex.ru/support/webmaster/ru/indexing-options/sitemap), [данные организации](https://yandex.ru/support/webmaster/ru/supported-schemas/address-organization).

## Перед подключением фотоайди.рф

При фактической проверке DNS домена разрешался в `92.53.96.136`; HTTP отвечал 200, HTTPS не прошёл проверку имени в сертификате. Это требует исправления на стороне выбранного хостинга. Проверка TLS не отключалась. DNS, CNAME и настройки production не менялись.

1. Выбрать место размещения: текущий GitHub Pages или существующий хостинг домена. Настроить соответствующие DNS-записи и действующий HTTPS-сертификат для домена. Не указывать GitHub IP, если сайт будет размещён у другого провайдера.
2. Убедиться, что корень нового HTTPS-домена отдаёт именно PHOTO ID, прайс и все локальные ресурсы. Сохранить пути файлов; сайт не требует сборки.
3. Выполнить `python scripts/update_seo.py --base-url https://xn--80aimcxa1ao.xn--p1ai/`. Команда обновит canonical, OG, JSON-LD и sitemap одновременно. До готовности HTTPS команда не применялась: рабочая версия не ссылается на неготовый сайт.
4. Разместить `docs/robots-domain.txt` как `/robots.txt` в корне нового домена. Добавить 301 с HTTP на HTTPS и выбрать одну версию www/без www средствами хостинга. Проверить редиректы с рекламными query и якорями; не терять UTM/yclid. Для `/index.html` предпочтителен 301 на `/`, если хостинг поддерживает настройку; canonical уже предусмотрен.
5. Повторить статические и браузерные проверки, затем публиковать комплект файлов. При переезде уже индексируемого сайта использовать процедуру смены адреса в Вебмастере; не менять canonical старого сайта раньше готовности нового.

Robots.txt должен находиться **в корне хоста**. Файл по адресу `/photoid/robots.txt` не управляет текущим GitHub Pages. При проверке корневой robots.txt возвращал 404, запрета обхода этим файлом не обнаружено. Сейчас sitemap можно передать непосредственно в Вебмастер. После переноса подготовленные правила Clean-param помогут обработке рекламных дублей, но не заменяют аналитику.

Основание: [robots.txt](https://yandex.ru/support/webmaster/ru/controlling-robot/robots-txt), [переезд](https://yandex.ru/support/webmaster/ru/site-move/general).

## Яндекс Метрика

Номер счётчика владелец ещё не передал. `metrika_id` пустой: сайт не подключает Метрику и не отправляет тестовые события на выдуманный счётчик. Сбор реальной статистики пока не подтверждён.

Когда создан настоящий счётчик для конечного сайта, укажите его номер в `config/site.json` и запустите `python scripts/update_seo.py`. `js/analytics.js` асинхронно подключит официальный tag.js и обработчики событий на обеих страницах. Вебвизор и карта кликов не включены. Политика обработки данных и настройки сбора должны соответствовать реально используемым сервисам и данным владельца; фиктивный юридический документ не добавлялся.

В интерфейсе Метрики создайте цели типа «Целевое событие» с точными идентификаторами:

| Идентификатор | Событие | Назначение |
| --- | --- | --- |
| `call_click` | Нажатие ссылки телефона, включая мобильную панель | Намерение позвонить; не подтверждает состоявшийся звонок |
| `telegram_click` | Открытие Telegram | Намерение написать; не отправка сообщения |
| `max_click` | Открытие Max | Намерение написать; не отправка сообщения |
| `map_click` | Переход в Яндекс Карты | Интерес к расположению/отзывам |
| `price_open` | Переход к полному прайсу | Интерес к услугам, не заявка |
| `contact_intent` | Переход к контактам | Промежуточное действие, не заявка |

Передаётся только место кнопки (`header`, `footer`, `mobile`, `package`, `content`), без номера телефона, текста сообщения и дополнительных персональных параметров. В тестах используется перехват API только внутри браузера тестирования; это проверка контракта, а не реального приёма событий Метрикой. Проверить события на собственном счётчике нужно после подключения. Ошибка или блокировщик аналитики не блокируют ссылки сайта.

Основание: [инициализация Метрики](https://yandex.ru/support/metrica/ru/code/counter-initialize), [целевые события](https://www.yandex.ru/support/metrica/ru/general/goal-js-event).

## Реклама и локальный поиск

После рабочего HTTPS и подключения счётчика:

1. Подтвердить сайт в Яндекс Вебмастере. Реальный verification token берётся из кабинета владельца; пустой или выдуманный тег в HTML не добавлялся. Загрузить sitemap, проверить канонические страницы, микроразметку и регион Новосибирск.
2. Проверить существующую карточку PHOTO ID в Яндекс Бизнесе, подтвердить права, связать конечный сайт и сверить адрес, часы, телефон и прайс. Не создавать дублирующую карточку и не заменять настоящие отзывы.
3. Связать счётчик с Директом. Первичные цели — клики телефона и мессенджеров; просмотры прайса и контактов анализировать отдельно. Для оптимизации на реальные обращения в дальнейшем понадобится коллтрекинг или учёт обращений; клик не равен продаже.
4. Разделять группы рекламы по реальным услугам: документы, фотопечать, печать/копии, сканирование/ламинирование, сувениры. Начальный геотаргетинг и бюджет уточнить по зоне обслуживания; цены «от» показывать с тем же условием в объявлении и на странице.

Быстрые ссылки, уже существующие в сайте:

| Тема | Путь от корня конечного сайта |
| --- | --- |
| Фото на документы | `/#pricing` |
| Примеры ретуши | `/#examples` |
| Печать фотографий | `/price.html#photo-print` |
| Печать и копии | `/price.html#document-print` |
| Сканирование | `/price.html#scan` |
| Как добраться | `/#contacts` |

Шаблон URL для **будущего рабочего домена**, не ссылка для запуска рекламы сейчас:

```text
https://xn--80aimcxa1ao.xn--p1ai/?utm_source=ya&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}#pricing
```

Метки идут перед `#pricing`. В Директе включить yclid. Код не обрезает query, не копирует пользовательские данные в мессенджеры и не пишет их в хранилище. Метрика учитывает атрибуцию визита после подключения; вручную размножать UTM на внутренних ссылках не нужно.

Основание: [метки Директа](https://yandex.ru/support/direct/ru/statistics/url-tags), [контакты организации](https://yandex.ru/support/webmaster/ru/search-appearance/address).

## Ограничения

Сайт технически подготовлен к продвижению, но не обещает позиции, индексацию или результат рекламы. Без доступа к кабинетам нельзя подтвердить статус в поиске, регион, регистрацию целей и настройки кампаний. Фактическая проверка в валидаторе Яндекса, приём целей Метрикой и переезд домена ещё предстоят. Новые отдельные посадочные страницы имеет смысл делать по данным спроса и рекламы, с реальным содержимым; в этой работе страницы под выдуманные районы не создавались.
